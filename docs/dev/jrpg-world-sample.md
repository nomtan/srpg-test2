# Aurelia — JRPG探索マップの別シーンサンプル

Godot 4.6.1。`samples/JRPGWorldSample.tscn` を開いて **F6** で実行。
F5 は従来どおり既存のメインシーンを実行する。
開始地点にはTripo製の冒険者・黒魔導士・執事・執事長・勇者・騎士・学者・戦士・白魔導士を配置。
全員に待機・歩行・走行を用意し、操作キャラクターは指定の `tripo_knight2` の騎士を使用する。
Blender編集ファイル、セルルック設定、顔の交換方法は [Tripoキャラクター9体](tripo-roster.md) を参照。
`Main.tscn`、既存の戦闘システム、作業中の `OpenWorldSample` は変更していない。

![橋と町](../../assets/world_jrpg/preview_bridge.png)

400×400（160,000セル）の有限マップ。旧128×128に対して面積約9.77倍。
キャラクターと建物の大きさを保ち、東方の草原・大高原・南の森林・遠方の海岸へ拡張している。

### ゲームパッド

接続したパッドで操作できます。ボタン名はXbox表記です（PS系では A＝×、B＝○、X＝□、Y＝△、LB/RB＝L1/R1、LT/RT＝L2/R2）。キーボード・マウスも引き続き使えます。

| 操作 | 探索中 | 戦闘中 |
|---|---|---|
| 左スティック | キャラクター移動（倒し具合で速度調整） | カメラ平行移動（キャラクター・選択カーソルは動かさない） |
| 右スティック | カメラ回転・仰角 | 探索時と同じカメラ回転・仰角 |
| A | 会話・次へ | 決定・実行 |
| B / ○（右側4ボタンの右） | 配置した9体の操作キャラを順送り（会話中は会話を閉じる） | キャンセル |
| RBを押しながら移動 | 走る（16m/s、以前の走行速度8m/sの2倍） | カメラを90度回転 |
| 右スティック押し込み | 追従視点に戻す | 旅人へカメラを戻す |
| X / □（右側4ボタンの左） | 剣で横薙ぎ | — |
| Y / △（右側4ボタンの上） | 剣で上段斬り | 待機（向きを選んで決定） |
| LT / RT | 縮小 / 拡大 | 縮小 / 拡大 |
| LB | 全景・追従切替 | カメラを90度回転 |
| 十字キー | 上：全景、右：町、下：高地、左：橋 | マス・メニュー選択 |
| Back / Share | 探索UIの表示切替 | — |
| Vキー / 左スティック押し込み（L3） | 配置した9体の操作キャラを順送り | 同左 |

戦闘では移動・攻撃・スキル・待機・退却をメニューから選べます。スティックの微小なずれは無視し、マス選択は長押しでリピートします。アナログ入力は最初に接続されたパッドを使用します。

戦闘開始時は、操作していたカメラの位置・向き・距離をそのまま引き継ぎます。固定の俯瞰視点には切り替えません。
戦闘中の行動・移動先・攻撃対象の選択は十字キーで行い、左スティックを倒してもメニューやマスの選択は変わりません。
左右スティックによるカメラ操作は敵の手番中も有効です。

歩行速度は従来どおり4.5m/s。キーボードのShiftでも走れます。LB/RBでの時間帯・天気変更は解除し、画面の時間帯・天気ボタンは引き続き使用できます。

### 操作キャラクターの切り替え

このサンプルの初期操作キャラは、配置済みの騎士と同じ `assets/characters/tripo_knight2/prepared/character.glb` です。`scenes/characters/tripo_roster/knight_player.tscn` で2.25倍（高さ約2.2）に拡大し、正面+Zを移動制御に合わせて+Xへ回転しています。26本のボーン、元のBase Color、3段階の明暗と細い輪郭線、`idle` / `walk` / `run` を使用します。モデルの編集・再生成は [Tripoキャラクター9体](tripo-roster.md) を参照してください。切り替え対象は `Character Roster` の並び順で、配置済みNPCも引き続き表示します。

シーンルートのInspectorの `Player Model` で表示モデルを指定します。騎士には上記のプレイヤー用シーンを指定します。以前の `assets/characters/meshy_hero2/hero2.glb` や `meshy_hero/hero.glb` も選択できます。空にすると従来の `base_1.bbmodel` 由来のモデルを使います。移動制御に渡すモデルは正面+X、足元が原点です。

- 通常移動：30fps・30フレーム（1秒）の専用 `walk` をループ再生。
- 走行：30fps・20フレーム（約0.67秒）の専用 `run`。腕振り・膝の曲げ・前傾・マントの揺れを歩行より大きくしている。
- 探索時は実際の水平移動速度に再生速度を合わせる（歩行4.5、走行12.8を1倍の基準とし、最大走行16.0では1.25倍）。走行の胴体の揺れを強調していた2倍再生は抑え、壁などで移動できない場合は静止する。
- 追従カメラは水平方向では主人公と同時に移動し、フレーム時間の変化による画面内の前後揺れを防ぐ。段差の高さ方向だけ指数補間で滑らかに追従する。
- 歩行と走行を切り替えるときは歩行周期内の位置を引き継ぎ、足の振りを先頭に戻さない。戦闘中の移動は従来の再生速度を使う。
- 停止：両足を地面につけ、腕を下ろした `idle` 姿勢に戻る。移動方向に合わせて3Dモデルを回転。
- 探索中は右ボタン `B・○` で配置した9体のモデルを順送り。`V` / 左スティック押し込み（L3）でも切り替えできます。冒険者→黒魔導士→執事→執事長→勇者→騎士→学者→戦士→白魔導士→冒険者の順で循環します。初期モデルは騎士です。会話・戦闘中は `B・○` を閉じる・キャンセルに使い、キャラ切替は `V` / L3で行います。切り替えても位置やHPを保持します。
- 初めから2Dで起動する場合、シーンルートのInspectorで `Use 3d Player` をオフにする。ゲーム中の切り替えは保存しません。

`Character Roster` を空にしたシーンでは、探索中の `B・○`、または `V` / 左スティック押し込みによる2D・3D切り替えを使用します。キャラクター切り替えの検証は `scripts/world_jrpg/verify_tripo_switching.gd` で実行できます。

### 剣の装備と攻撃

操作中のTripoキャラクターの右手に `assets/weapons/sword/test_sword/swordl.glb` を装備します。元GLBはそのまま使用し、柄の中心・斜めの軸・大きさは `scripts/world_jrpg/sword_combat.gd` で調整しています。キャラ切替時にも剣を引き継ぎ、配置済みNPCの装備は変更しません。

- 左のフェイスボタン **X / □**、または **J**：横薙ぎ（`sword/slash`、0.64秒）。体を捻って右から左へ斬ります。
- 上のフェイスボタン **Y / △**、または **K**：上段斬り（`sword/overhead`、0.88秒）。頭上に構えて前方へ振り下ろします。

探索中はその場で攻撃し、動作中の移動・連打による割り込みを抑止します。終了後は待機へ戻り、移動入力が残っていれば歩行・走行を再開します。会話開始・キャラ切替時は攻撃状態を解除します。今回の攻撃は探索用のアニメーションで、ダメージ判定はありません。ターン制戦闘の操作・ダメージ計算は既存のままです。

攻撃は各キャラのボーン長に合わせた独立の `AnimationLibrary` として生成します。振り方・タイミングの編集は `sword_combat.gd` のキーフレームで行えます。検証：`godot --headless --path . --script scripts/world_jrpg/verify_sword_combat.gd`。描画確認：同コマンドの `--headless` を外し、末尾に `-- --capture` を付けると `artifacts/sword_attacks/` に画像を保存します。

#### 以前のMeshy hero2モデルの編集

編集用のリグと3アクションは `assets/characters/meshy_hero2/hero2.blend` に保存。未加工のバックアップは `artifacts/meshy_hero2/hero2_before_rig.blend`。`idle` は2秒、全クリップはその場で動くループで、終端に先頭と一致するキーを持つ。GLBは高さ約2.2、正面+Xに変換している。GodotはGLBを使用し、編集用blendの直接インポートはスキップする。hero2の膝の鎧は上腿側へウェイトを寄せ、走行で地面へ折れ込むのを防いでいる。

Blenderのシーン選択で `Original`（元のPBRマテリアル・法線・全テクスチャ）と `Toon` を比較できます。ToonはEevee／Standard、Key Light 1灯と弱い環境光を使用し、Constant ColorRampの68%・84%・100%を元の色に掛けます。顔・耳の一部だけSmooth、その他はFlatで、Subdivisionは使いません。形状・UV・ウェイト・3アクションのキーを保持しています。

GLB自体はマットな互換マテリアルです。Eevee固有のShader to RGBはGLBに入らないため、`hero2.glb.import` に設定した `hero2_import.gd` がGodot用の3段階シェーダーを適用します。輪郭はBlenderで厚さ0.003にした別メッシュで、同じ骨に追従します。他のエンジンへ持ち出す場合は、そのエンジン向けセルシェーダーが必要です。

現在のToonモデルの再生成（Blender 5.1、変更前のリグ付きスナップショットから見た目の設定・書き出しまで再実行）：

```powershell
blender --background --factory-startup --python tools/toon_meshy_hero2.py
```

比較画像・保存前後のデータハッシュは `artifacts/meshy_hero2/toon/` にあります。従来の `tools/rig_meshy_hero2.py` はリグのみの再生成用で、実行するとToon設定を上書きします。

`Player Model` に `hero2.glb` を指定した場合のモデル・ウェイト・アニメーション・表示切り替えの検証：

```powershell
godot --headless --path . --script scripts/world_jrpg/verify_meshy_hero2.gd
```

## 会話とイベントの編集

`assets/world_jrpg/story.json` を変更してシーンを再実行する。
シーンルートの `story_path` を別JSONへ変更して差し替えることもできる。

- `npcs`: `id`、`name`、`position: [x, z]`、`palette`、`lines`（会話文の配列）。
- `encounter`: `id`、`position`、`radius`、`title`、`lines`、`victory`、`defeat`。
- 座標はマップの地面座標。NPCは有効な地面かつ建物の外に配置する。

遭遇は橋の東 `(87, 80)` にある金色のマーカーに近づくと発生する。
導入会話 → 小規模戦闘 → 結果会話 → 探索復帰まで実装済み。
勝利した遭遇は再発しない。勝利時は最後に移動した場所からそのまま探索を再開する。
敗北・退却では同じマップの遭遇開始位置で回復。マーカーから一度離れて戻ると再挑戦できる。
状態は実行中のみ保持し、セーブデータには書き込まない。

## 戦闘サンプル

![戦闘](../../assets/world_jrpg/preview_battle.png)

探索していた地形に11×11の範囲を取り、通行可能な地面にだけ半透明のマスを表示する。
探索中の旅人ノードをそのまま使い、戦闘開始時の位置も維持する。別の盤面や地形は生成しない。
旅人1人と敵2体。青いマスをクリックして3マス以内を移動、隣接する敵をクリックして攻撃。
移動と攻撃は各ターン1回。Spaceまたはボタンで敵ターンへ進む。
敵は同じ地形の経路を探して2マスまで近づき、隣接時に攻撃する。全滅判定・撃破・HP・退却あり。
段差・水・崖・建物・木の幹の判定は探索と共通。橋の高さや地形の凹凸をマス選択にも反映する。
移動は経路に沿ったアニメーション。攻撃は通行可能な隣接マスに限定し、崖越しには攻撃できない。
戦闘中は周囲10mの樹冠を描画から除き、キャラクターの視認性を確保する。幹と当たり判定は維持する。
戦闘終了時にはマスと敵だけを取り除き、樹冠を元に戻す。

これは同一マップ上での探索と戦闘を試す簡易実装で、既存のAP・ジョブ・成長・保存には未接続。
本番のSRPGへ接続する際は `world.gd` の `_start_battle()` / `_finish_battle()` が差し替え箇所。

## 新アセットとキャラクター生成

- `scripts/world_jrpg/voxel_prop.gd`: 木・岩・家・塔の手続き生成。`@tool`付きで単体利用も可能。
- `voxel_batch.gd`: 色ごとにMultiMeshへまとめる描画補助。
- `surface.gdshader`: 草地、石積み、自然岩、木目、屋根、葉の微細な模様。遠景では細部を抑える。
- `water.gdshader`: 時間変化する波紋と視線角度に応じた水面の反射表現。
- `world.gd`: 地層のある崖、草原、雪山、火山、海と川、城、町、展望台、桟橋の組み立て。
- `assets/world_jrpg/palette.json`: 地形と建物の配色。
- `pixel_actor.gd`: オリジナル24×32ピクセルの4方向・3フレーム歩行キャラクター。

旅人・案内人・商人・衛兵・敵の5種。マントと剣、フード、エプロン、肩鎧などを描き分けている。
画像はコードから生成するため外部生成サービスは不要。
`pixel_actor.gd` の `PALETTES` と矩形の構成を変更すれば再生成できる。
将来のGUI生成ツールは未実装だが、PNGアトラスの書き出しツールは利用できる。

```powershell
godot --headless --path . --log-file ./jrpg-export.log --script tools/asset_gen/export_world_characters.gd
```

`assets/world_jrpg/*_atlas.png` に72×128の透過PNGを出力。
横3コマ、縦は手前・右・左・後ろの順。ゲームでは同じ生成関数から直接テクスチャを作成する。

## 見た目と広域化

参考画像の暖かい斜光、長い影、草木の密度、水辺の木造建築を手続き生成で取り入れている。
雲のある空、距離による霞、細かな葉の集まり、町と川沿いの草・葦・花、護岸、橋の板・手すり、
街灯と木箱を追加。照明と材質は全域に適用し、細かな植生と小物は町・橋周辺に集中している。
水面はGL Compatibility用の簡易表現で、画面全体のレイトレーシングやSSRではない。

初期位置から到達可能な地面137,422セルを確認。
東端街道 `(370, 80)`、南の街道 `(210, 350)`、東の高原 `(305, 65)`、南東の森林 `(350, 300)` への経路を検証。
32×32単位の描画バッチ、材質・メッシュの共有、地形高さキャッシュ、チャンク別の障害物検索を使用。
細かな草の描画は100m以内。全地形は開始時に生成し、ストリーミング生成は未実装。

描画負荷の参考値：RTX 4050 Laptop、GL Compatibility、1280×720、橋の固定視点で、
ウォームアップ後の120フレームが2,000ms（60fps）、988ドローコール。
この固定視点・検証環境での測定であり、全景や他のGPUでのフレームレートは未計測。
