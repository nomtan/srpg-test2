# SRPG Admin (Phase 1)

Godot SRPG用のローカルデータ管理画面です。GitHub API、Cloudflare Workers、Hono、DBは使用しません。

## 起動

Node.js 20以上、pnpmを使用:

```bash
cd admin
pnpm install
pnpm dev
```

http://127.0.0.1:5173/ を開きます。ローカルVite開発サーバーが `../data/admin/{category}/{id}.json` を直接読み書きします。Gitのcommit/pushは手動またはGitHub連携AIエージェントが実行します。

## 現在実装済み

- タスクの一覧、ステータス別集計・フィルター、作成、JSON編集、削除
- スキル、キャラ、ジョブ、装備、アイテム、ストーリー、ステージの汎用JSON編集
- ID一致・基本的なタスクステータスの検証
- ローカル保存（外部サーバーへの送信なし）
- Godot側の実装待ちタスクを `data/admin/tasks/` に初期登録

## 注意事項

- **Phase 2**: ジョブ・スキル・装備のJSONは管理画面用スナップショットです。Godotのコード・戦闘ロジックは変更していません。
- `data/admin` の各カテゴリは新設の編集用領域で、既存の `assets/world_jrpg/story.json` などとは別です。
- スキルの反撃・回復は仕様データとして設計中で、ゲーム内では未実装です。
- 保存はローカルVite開発サーバー経由のみ。静的ビルドで編集APIは動きません。
- JSON編集はスキーマ全体を検証しません。既存ゲームデータの自動移行は次のPhaseで行います。

## リアクション仕様（確定）

- スキル種別は攻撃・回復・バフ・デバフ・パッシブ
- パッシブは専用スロット装備で有効
- 攻撃種別: ACTIVE（自分の行動による攻撃） / REACTION（リアクション攻撃）
- 反撃はACTIVEに対してのみ発動可能、REACTIONへの反撃は禁止
- 攻撃が命中しても回避されてもリアクション攻撃・回復の発動判定を行う
- リアクション攻撃・回復はAP・MPを消費しない
- 発動確率、複数効果、条件フィルターをJSONで表現できるよう段階的に実装
- 回復系リアクションはREACTION被弾でも発動可能（反撃とは別扱い）

実装タスクは管理画面の「実装タスク」から確認してください。

## 開発ブランチ運用ルール

- `feature/admin` では `admin/`、管理用 `data/admin/`、関連ドキュメント・タスクだけを編集する。
- Godotの `scripts/`、`scenes/`、`project.godot`、ゲームアセットは変更しない。
- Godot側の実装が必要になった場合、まず `data/admin/tasks/` にTODOを登録する。
- Godotの変更は別途承認後、別ブランチで実施する。
